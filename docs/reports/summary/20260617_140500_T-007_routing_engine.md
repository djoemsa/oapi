## What was done
- Created the thread-safe `RotationEngine` in [engine.go](file:///d:/Codes/oapi/internal/rotation/engine.go) to match model alias routes and select keys dynamically.
- Implemented model alias resolution prioritizing exact matching over wildcard `*` fallback.
- Implemented primary chain slot traversal walking from left to right.
- Implemented slot round-robin key selection skipping tried keys and rate-limited keys.
- Implemented fallback pool flat round-robin across all matching fallback keys.
- Implemented custom `RateLimitError` calculating and reporting the earliest cooldown recovery time across all matched keys.
- Implemented unit tests in [rotation_test.go](file:///d:/Codes/oapi/tests/rotation_test.go) verifying route matching, primary chain walking, slot round-robin, fallback pool, and rate limit error calculation.

## Approach taken
- Used `sync.Map` with atomic uint64 counters to manage slot and fallback round-robin indices thread-safely without holding global locks.
- Kept the key selection algorithm clean by taking a `triedKeys` map as input to easily handle retries inside the client proxy.
- Calculated the minimum (earliest) cooldown time using `CanUseKey` output whenever all keys are exhausted.
