# Summary: T-006 — Key Pool & Rate Limiter

**Timestamp:** 20260617_135500
**Status:** Completed

## What was done
- Implemented a thread-safe `KeyPool` in [pool.go](file:///d:/Codes/oapi/internal/rotation/pool.go) to register key configurations, manage current states, and resolve limits precedence (provider defaults -> model overrides -> user overrides).
- Designed and started a background tick loop (running every 5 seconds) to handle cooldown expirations, garbage collect expired transient sliding window timestamps, and manage RPD daily limit resets.
- Implemented sliding window RPM checking using transient timestamp slices in [limiter.go](file:///d:/Codes/oapi/internal/rotation/limiter.go).
- Implemented daily RPD limits checking and timezone-aware recovery (Rolling 24h for Groq, Midnight PT for Google, local midnight for others).
- Added `MarkCooling` function to put rate-limited keys into cooldown upon receiving provider 429 errors.
- Created extensive unit tests in [limiter_test.go](file:///d:/Codes/oapi/tests/limiter_test.go) verifying sliding window RPM limits, daily limits, cooldown mark/recovery, and background resets.

## Approach taken
- Used `sync.RWMutex` to isolate read and write segments across the key registry and state manager.
- Integrated standard Go embedded timezone data (`time/tzdata` package) to ensure robust cross-platform timezone lookup for PT (Pacific Time) on Windows and Unix systems.
- Handled sliding window limits efficiently using slice slicing without requiring external caching engines.
